# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/), and this project adheres to [Semantic Versioning](https://semver.org/). Entries are telegraphic: one line per change — what changed plus the key term/API — with no narrative, mechanism explanations, or "no verdict change" boilerplate.

Older entries (v1.8.22 and earlier) are archived in [docs/changelogs/CHANGELOG-1.8.22-and-earlier.md](docs/changelogs/CHANGELOG-1.8.22-and-earlier.md).

## [Unreleased]

### Maintainability refactor (per `chat/plan2.md`)
- Refactor: removed the redundant `picus_core::poly::IrPoly` alias — it was a second public name for `Polynomial`, identical to `Poly`, and 11 of 13 use sites re-imported it as `IrPoly as Poly`. All sites now use `Poly`; also removes the `PolyIR`/`IrPoly` word-reversal collision. (T1)
- API: `check_circuit`/`check_r1cs_bytes` now take `PicusConfig` (matching `check_r1cs`/`solve_with`) instead of the `Config` alias, for one consistent config type in signatures; the `Config` alias stays exported (non-breaking). `CancelToken::none()` doc corrected to state it is an alias of `new()`/`default()`, not an uncancellable token. (T3)
- Refactor: dropped the never-constructed `R1csParseError::BadFieldSize` variant and the denormalized `ConstraintBlock.nnz` field (it always equalled `wire_ids.len()`); `constraint_to_string` now tests `wire_ids.is_empty()`. (T10)
- API: trimmed the `PolyIR` builder surface — removed `assert_zero` (fully subsumed by `assert`, no call sites); `fresh_var` and `SystemId` are now `pub(crate)` (internal-only; `SystemId` was unconstructable from outside anyway). (T16)
- Cleanup: removed dead `picus-core` API — `PrimeField::{characteristic, add_ref, sub_ref, add_assign_owned}` (zero callers; duplicates of `prime`/`add`/`sub`/`add_assign`) and `MatrixOrder::{from_rows, n_rows}` (zero callers); `MatrixOrder::{lex, is_admissible}` are now `#[cfg(test)]`. (T6)
- Docs: corrected the `metric` module doc (removed nonexistent `record_add`/`GbStatsLayer`; documented all 13 macros and the three distinct gating flags), fixed the `#[metric]`-under-gb-stats misfiling, and marked the 13 `__metric_*` `#[macro_export]` macros `#[doc(hidden)]`. (T5)
- Naming: renamed `tecomplete`'s private `type Mono = Vec<(usize,u16)>` to `ExpVec` so `Mono` unambiguously means `Monomial` workspace-wide; clarified `PolyRingType`'s solver-only doc. (T2, partial — core-alias removal deferred, needs picus-solver edits)
- API boundary: added `publish = false` to the internal substrate crates (`picus-core`/`picus-r1cs`/`picus-smt`/`picus-analysis`/`picus-solver`/`cvc5-ff`/`cvc5-ff-sys`/`picus-metric-macros`); replaced the facade's blanket `pub use picus_r1cs/picus_smt/picus_analysis/picus_solver` with a curated `picus::advanced` module (`parse_var_index`, `validate_combination`, `create_backend`, `SolverBackend`, `PolySystem`). `picus-cli` reach-throughs now go through `picus::advanced`. (T13)
- Analysis: added `PropagationCtx::mark_known` (enforces the known/unknown partition invariant in one place; replaces the hand-copied `unknown.remove`+`known.insert` idiom in 6 lemmas) and a generic `LenGatedCache<T>` (replaces the duplicated length-keyed cache in `linear`/`tecomplete`); moved the `legendre` field primitive onto `PrimeField`; made `SelectorState`'s fields private. (T8, partial — `shape.rs` linear-form primitive and the known-state-ownership refactor deferred as soundness-sensitive)
- Errors: removed the dead `SolverError::Unsupported` variant; narrowed the public `IrError::Solver` to wrap a new, tightly-scoped `picus::SolveError` (`Config` + typed `Solver(SolverError)`) instead of the whole `PicusError` — the `PolyIR::solve` path no longer leaks impossible `Parse`/`Io`/`Dpvl` variants; `SolverError` is now re-exported at the crate root. (T14, partial — full `validate_combination`/`create_backend` typing, `UnknownReason::BackendError` merge, and the DPVL failure counter deferred)
- SMT: added `Theory::as_str` / `Theory::smtlib_name`; `picus-cli`'s solver/theory header is now derived from `SolverKind::as_str` + `Theory::smtlib_name` (deleting the hand-maintained `(solver, theory)` match with its `_ => "unknown"` fall-through and edit-site #5). (T9, partial — the feature-gated cvc5/z3 backend dedups deferred pending a `--features cvc5,z3` build)
- CLI/config: collapsed the 15 copy-pasted tri-state `--flag on|off` conversions into one `on_off` helper; dropped the dead `#[derive(Default)]` on the four gb-stats counter structs (`SplitDfsCounters`/`SplitGbCounters`/`NativeFfBackendCounters`/`IdealCounters`, only ever built via `new_const`). Introduced two declarative macros — `atomic_counters!` (generates each counter struct + its `new_const` zero-initializer from one field list; the 4 structs no longer double-list their fields) and `runtime_config!` (generates `RuntimeConfig` + its `Default` + `EngineOverlay` + `apply_overlay` for all 28 engine knobs from one annotated field list, ending the 4-way per-knob duplication). Behaviour identical; the `apply_overlay` drift-guard test still passes. (T4)
- Tests: broke the `picus-smt → picus-analysis` dev-dependency cycle (a crate-layering inversion) by moving the two integration tests that need the analysis R1CS lowering (`multi_prime`, `sparse_lowering`) into `picus-analysis/tests/`; picus-smt now has no back-edge. Added a shared, feature-gated `picus_r1cs::testkit` fixture module (`block`/`empty_block`/`blk`/`constraint`/`r1cs`/`p7`) and removed 21 copy-pasted local fixture helpers across 10 test files in 3 crates (gated behind a `testkit` cargo feature enabled as a dev-dependency, so it never ships in a normal build). (T15 — the `test_lowering.rs` port deletion still needs the lowering relocation; deferred)
- Core-ff: moved the byte-identical `capacity`/`fitting_bucket` geobucket-cascade helpers into the shared `geobucket_params` module (were duplicated in `geobucket` and `sparse_geobucket`); hot path, verified bit-identical under the `repr_oracle`/geobucket differential tests. (T7, partial — the larger `select_divisor`/merge-loop/geobucket-skeleton dedups deferred as hot-path-sensitive)
- CLI: split the 688-line `picus-cli/src/main.rs` monolith into `args.rs` (clap types), `output.rs` (JSON structs + print helpers), and `commands.rs` (`cmd_check`/`cmd_info` + helpers), leaving `main.rs` a thin parse-and-dispatch (137 lines). Pure move, no behavior change. (T12)
- Core: split the 800-line `picus-core/src/profile.rs` into `profile/{counters,metric,phase}.rs` (gb-stats counters, the `metric::` macro DSL, and the `ScopedTimer` phase profiler — three previously-fused subsystems) behind `pub use` re-exports, so every `profile::…` path and the `#[metric]` expansion (`::picus_core::profile::ScopedTimer`) resolve unchanged. Pure move, no behavior/API change. (T5, full split)
- Analysis: added `propagation::shape::linear_form` — one descriptive "parse a poly as a linear combination" primitive (returns raw `(var, coeff)` terms + accumulated constant, `None` on nonlinear; makes NO policy decision) — and routed all 6 previously hand-rolled copies through it (`aboz`, `bim`, `basis2::match_decomp`, `compconstant::{build_canon, find_sum_var, find_pinned_zero}`). Each keeps its own constant/wire policy, so behavior is unchanged (verified under the per-lemma + `soundness.rs` suites). (T8, shape.rs keystone)
- R1CS: removed the redundant `field_reduce` double-reduction — R1CS factors are already reduced at parse time and `PrimeField::from_biguint` reduces again, so the two lowering sites now pass the factor straight through; deleted the misplaced `picus_r1cs::field_reduce` helper (+ its tests) and the now-dead `prime` parameter threaded through `block_to_linear`/`constraint_to_poly`. (T10, field_reduce)
- Analysis: extracted the basis2 decomposition soundness gate into shared `all_bits_binary` + `decomp_is_faithful` helpers, called from both `basis2::run` and `compconstant::find_inner_bit` (was duplicated); basis2 keeps its companion-relaxation branch on top. (T8, decomp gate)
- Analysis: `run_dpvl` now counts per-query backend *hard errors* and, when the verdict is `Unknown`, logs a summary warning distinguishing a systematically-failing/misconfigured solver from a genuinely hard problem (was silently downgraded to `Skip`). Additive; verdict unchanged. (T14, DPVL failure counter)
- Analysis: single-sourced each propagation lemma name — dropped `PropagationLemma::name()` (which every lemma duplicated as a string literal already present on its `LemmaDescriptor`); the DPVL driver now pairs each instance with its descriptor name. Removed the 5 per-lemma name asserts and 2 factory-name drift tests they existed to police. (T8, register_lemma)
- cvc5-ff: fixed a latent use-after-free — `Statistics` and `Stat` (borrowed `*mut cvc5_stat(s)_t` views into the owning `Solver`/`TermManager`, with no cvc5 copy/release) now carry a `'tm` lifetime like every other handle wrapper; `Solver/TermManager::get_statistics` return `Statistics<'_>`. The borrow checker now rejects using stats past the owner's drop. (T11, soundness)

## [1.8.24] - 2026-07-04
- API: `picus::PolyIR` (module `picus::ir`) is now the ergonomic public constraint-system builder over GF(p) — `Copy` `Var` handles + a ring-free symbolic `Expr` with `std::ops` operator overloading (`x*x - x`, `2*x + 3*y - 5`, `x.pow(3)`), constants via `Into`; `eq`/`ne`/`assert_zero`/`assert`/`assign`/`or`/`bitsum`/`field_polys`; `solve`/`solve_with` → `Solution { Unsat, Sat(Model), Unknown }` with `Model` indexable by handle (`m[x]`) or name (`m["x"]`). `Arc`/`FfPolyRing`/`Poly` hidden (lowered in `ir::lower`); solver unchanged. `ne` uses the native disequality primitive for bare-var pairs, else a Rabinowitsch witness.
- The former low-level `PolyIR` (ring + `Vec<Poly>`) is renamed `PolySystem` (module `picus_smt::poly_system`) and is no longer a top-level public builder; `PolyIR::lower()` is the power-user bridge and the internal `solve_system` decides it. Removed the top-level `picus::{solve, FfPolyRing, PrimeField, IrPoly}` re-exports; `solve_api` test replaced by `ir_api` + a runnable `PolyIR` doctest.

## [1.8.23] - 2026-07-04
- Refactor: `picus_smt::poly_ir::PolyIR` slimmed to a use-agnostic GF(p) constraint system; the uniqueness overlay (two-copy layout, `n_wires`/`input_indices`/`known_signals`/`target_signal`, wire methods, R1CS lowering, `LowerError`) moves to new `picus_analysis::uniqueness::{UniquenessQuery, r1cs_to_uniqueness_query}`; lemmas + DPVL take `&UniquenessQuery`. Verdicts unchanged.
- New: `picus::solve(&PolyIR, config) -> SolverResult` decides a caller-built constraint system directly (no R1CS/uniqueness layer); `PolyIR::new` + builder mutators; `picus` re-exports `PolyIR`/`FfPolyRing`/`PrimeField`/`IrPoly`/`SolverResult`. Documented in `docs/usage.md`.
- `cvc5_ff`/`cvc5_nia`/`z3_nia` emit the disequality from generic `PolyIR::disequalities` (was `target_signal`/`x_name`/`y_name`), matching `native_ff`.
- Test env var `PICUS_SKIP_PLDI_SMOKE` → `PICUS_TEST_SKIP_SMOKE`; picus-smt unit tests lower locally via `src/test_lowering.rs` (no picus-analysis dep), lowering/wire tests moved to `uniqueness_tests`.
- Maintainability: doc/inline comments across the workspace trimmed to pure-technical prose — removed benchmark anecdotes (PLDI A/B wall-clock deltas), changelog-style historical narration, and non-technical asides; soundness/algorithm rationale kept.
- Test: `picus-smt/tests/external_solve.rs` (feature-gated) — real cvc5/z3 backend solves over a GF(7) suite (SAT/model, UNSAT, and both disequality paths), verifying the `PolyIR::disequalities` backend change end to end.
